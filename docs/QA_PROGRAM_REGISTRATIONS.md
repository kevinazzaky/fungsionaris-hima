# QA dan checklist operasional pendaftaran program kerja

Catatan ini merangkum hasil verifikasi teknis fitur pendaftaran peserta program kerja internal (`/program-kerja/[id]/daftar` dan `/admin/program-kerja`), checklist migrasi manual, serta panduan penyiapan **IT Versary & Sertijab 2026**.

## 1. Peringatan keamanan database

Jangan menggunakan `DATABASE_URL`, `DIRECT_URL`, atau kredensial project Supabase produksi saat menjalankan pengujian lokal, preview PR, atau staging. Perintah migrasi (`npm run db:migrate`), seeding (`npm run db:seed-programs`), maupun uji coba formulir di browser/panel admin lokal akan langsung menulis atau mengubah isi database tujuan yang terhubung pada `.env.local` atau Environment Variables deployment.

Gunakan project Supabase/PostgreSQL staging yang terpisah untuk seluruh pengujian manual sebelum rilis.

Rincian verifikasi migrasi dan RLS pada `tests/database.test.ts` terhadap `prisma/migrations/20261117000000_program_registrations/migration.sql` dan `prisma/migrations/20261118000000_program_custom_form/migration.sql`:

- Tabel `ProgramRegistration` memiliki `relrowsecurity = true` (`ENABLE ROW LEVEL SECURITY`), dan hak akses `anon`, `authenticated`, serta `PUBLIC` dicabut (`REVOKE ALL`).
- Program yang sudah ada sebelumnya otomatis menerima nilai default `registrationMode = 'external'`, `registrationGroupLink = ''`, dan `registrationMaxQuota = null`.
- Constraint `Program_registrationMaxQuota_check` menolak nilai kuota di bawah `1`.
- Indeks unik `(programId, nim)` menolak NIM ganda pada program yang sama, namun mengizinkan NIM yang sama mendaftar pada program kerja berbeda.
- Foreign key `ProgramRegistration_programId_fkey` memakai `ON DELETE RESTRICT`, sehingga penghapusan `Program` yang masih memiliki peserta ditolak database.
- Migration `20261118000000_program_custom_form/migration.sql` menambahkan `Program.registrationFormConfig` dan `ProgramRegistration.customResponses` bertipe `JSONB NOT NULL DEFAULT '{}'::jsonb`; baris `Program` dan `ProgramRegistration` lama tetap memiliki default `{}` tanpa merusak data yang sudah ada. Fitur opsional kuota per angkatan (`cohortQuotas`) disimpan di dalam kolom JSONB `Program.registrationFormConfig` yang sama sehingga tidak memerlukan file migrasi SQL baru.
- Penyimpanan serta pembacaan JSONB untuk `registrationFormConfig` dan `customResponses` terverifikasi pada PGlite (baik baris dengan jawaban custom maupun baris dengan `{}`), dan role `anon` ditolak (`permission denied`) pada kueri `SELECT "registrationFormConfig" FROM "Program"` maupun `SELECT "customResponses" FROM "ProgramRegistration"`, sementara `authenticated` mengembalikan `0` baris.

### Status temuan audit dan sisa pengujian manual

Verifikasi pada cabang `feat/custom-program-form` (`116db90` dan `fe7364a`, 18 November 2026) memastikan seluruh temuan audit sebelumnya (`20b47b1`, `22223ee`, dan `2f06e91`) sudah terselesaikan serta memisahkan pengaturan formulir ke tab **Atur formulir** dengan penjagaan perubahan belum disimpan, sedangkan pengujian pada PostgreSQL staging dan browser terautentikasi tetap perlu dijalankan manual sebelum rilis:

1. **Selesai: Respon 401 endpoint admin baru pada `next start` produksi**: `src/data/auth.ts` menetapkan nama `AccessError` dan route handler untuk `/api/admin/program-registrations`, `/api/admin/program-registrations/[id]`, serta `/api/admin/program-registrations/export` memeriksa `isAccessError`. Pada build `next start` (`20b47b1` dan `22223ee`), permintaan tanpa sesi ke `GET /api/admin/program-registrations`, `PATCH`/`DELETE /api/admin/program-registrations/<uuid>`, dan `GET /api/admin/program-registrations/export` seluruhnya mengembalikan HTTP `401` (`no-store`).
2. **Selesai: Penanganan ID tidak ditemukan pada `/program-kerja/[id]/daftar`**: `generateMetadata` pada `/program-kerja/[id]/daftar` memanggil `notFound()` saat program tidak ditemukan atau belum dipublikasikan. Karena `RootLayout` memakai streaming setelah `await headers()`, `GET /program-kerja/does-not-exist/daftar` pada `next start` (`20b47b1` dan `22223ee`) tetap mengirim HTTP `200` disertai tag `noindex`.
3. **Selesai: Pratinjau foto saat dialog editor program tetap terbuka**: perbaikan pembersihan state pratinjau file sementara pada `src/components/admin/programs-manager.tsx` sudah digabungkan sejak `20b47b1`. Pengujian interaktif langsung tetap masuk cek browser admin terautentikasi.
4. **Selesai: Penanganan opsi `select` terdahulu yang dihapus dan kontras border kartu form builder (`2f06e91`)**: `ParticipantEditor` di `src/components/admin/program-registrations-manager.tsx` kini mengikat `<select value={stringVal}>` dan merender `<option value={stringVal}>{stringVal} (opsi terdahulu - tidak tersedia)</option>` ketika jawaban tersimpan sudah dihapus dari `field.options`, sehingga admin melihat nilai aktual dan dapat menggantinya ke opsi kosong atau opsi valid dalam satu langkah. Border `.admin-custom-field-card` dan `.admin-legacy-responses` di `src/app/admin/admin.css` juga diperbarui ke `#8c8c82` agar memenuhi kontras minimal `3.0:1`.
5. **Sisa cakupan manual (PostgreSQL nyata dan browser terautentikasi)**: PGlite berjalan dalam satu proses/engine dan tidak menggantikan uji multi-koneksi transaksi `FOR UPDATE OF p` di PostgreSQL sungguhan untuk batas kuota total (`registrationMaxQuota`) maupun kuota per angkatan (`cohortQuotas`). Alur **Daftar program** (`ProgramEditor` ringkas beserta banner pintasan **Atur formulir `<judul>`** dan badge `Kuota N angkatan`), tab terpisah **Atur formulir** (`ProgramFormSettingsManager`, pemilih program internal, toggle opsional **Batasi kuota peserta per angkatan (opsional)**, preset 2023-2026 @ 5 peserta, penguncian kolom bawaan **Angkatan** ke `Wajib`, **Reset perubahan**, konfirmasi perubahan belum disimpan saat berpindah program/tab/**Lihat peserta program ini**, dan simpan via `PATCH /api/admin/programs/[id]/form`), form builder (kolom bawaan dan 6 tipe custom), submit publik dengan kolom tersembunyi/opsional serta rincian kuota per angkatan dan whitelist opsi **Angkatan**, login admin, tab **Peserta proker**, **Detail & Edit** (termasuk data bawaan terdahulu, jawaban kolom terdahulu, dan sunting pendaftar berangkatan historis), hapus peserta, serta unduh file `.xlsx` berkolom dinamis di browser perlu diverifikasi manual pada database staging yang sudah dimigrasi.

## 3. Checklist migrasi manual (staging ke produksi)

1. Buat backup atau snapshot database target sebelum menerapkan migrasi.
2. Tinjau isi SQL pada `prisma/migrations/20261117000000_program_registrations/migration.sql` dan `prisma/migrations/20261118000000_program_custom_form/migration.sql`, lalu pastikan tidak ada migrasi tertunda lain yang belum ditinjau.
3. Pastikan environment CLI (`DATABASE_URL` dan `DIRECT_URL`) mengarah ke database staging terlebih dahulu, bukan produksi.
4. Jalankan perintah berikut secara berurutan (jangan memakai `prisma db push` pada database staging/produksi):

```sh
npm run db:validate
npm run db:generate
npm run db:migrate
```

5. Periksa langsung di SQL Editor atau client database target bahwa:
   - Kolom `registrationMode`, `registrationGroupLink`, `registrationMaxQuota`, dan `registrationFormConfig` (`JSONB`, default `'{}'::jsonb`) ada pada tabel `"Program"`.
   - Tabel `"ProgramRegistration"` ada dengan kolom `customResponses` (`JSONB`, default `'{}'::jsonb`), `relrowsecurity = true`, dan tanpa izin `SELECT`/`INSERT`/`UPDATE`/`DELETE` bagi `anon` maupun `authenticated`.
6. Jalankan ulang `npm run build` dan uji server terautentikasi pada staging sebelum menerapkan langkah yang sama ke produksi.

## 4. Checklist operasional: Setup IT Versary & Sertijab 2026

Pada kode seed (`src/lib/program-seed.ts`), entri **IT Versary & Sertijab 2026** untuk periode `2025/2026` sudah disetel ke `registrationMode: "internal"`, `status: "open"`, dan `registrationFormConfig` default (`DEFAULT_PROGRAM_FORM_CONFIG`). Pada database baru, `npm run db:seed-programs` (`scripts/seed-programs.ts`) membuat record tersebut dengan UUID deterministik dari `program-2025-2026-4`, tanpa menimpa program yang sudah pernah dikelola admin.

Untuk menyiapkan atau memperbarui kegiatan melalui panel admin:

1. Masuk ke `/admin/login` lalu buka menu **Program kerja** (`/admin/program-kerja`).
2. Pada tab **Daftar program**, pilih tab periode **2025/2026** (gunakan **Tambah periode** jika periode belum tersedia).
3. Klik **Edit** pada **IT Versary & Sertijab 2026** (atau klik **Tambah program** bila program belum ada di database).
4. Pada dialog editor program (`ProgramEditor`), pastikan **Mode pendaftaran** dipilih ke **Formulir Website (Internal)** (`internal`) dan **Tampilkan di website** aktif, lengkapi metadata/foto program bila perlu, lalu klik **Simpan program** (pastikan juga tombol **Tampilkan periode** pada periode `2025/2026` aktif).
5. Setelah dialog menutup, buka tab **Atur formulir** lewat tombol **Atur formulir IT Versary & Sertijab 2026** pada banner sukses, tombol **Atur formulir** di baris program, atau tab **Atur formulir** di bagian atas lalu pilih `2025/2026 - IT Versary & Sertijab 2026` di dropdown **Pilih program kerja internal**.
6. Pada kartu **Akses, kuota & tautan grup**, atur **Status pendaftaran** ke **Pendaftaran Dibuka** (`open`), isi **Kuota maksimal peserta (opsional)** dengan angka bulat minimal `1` bila panitia membatasi kuota total (atau kosongkan jika tanpa batas), dan isi **Tautan grup WA/LINE peserta (opsional)** dengan URL `http://` atau `https://` yang valid bila panitia ingin menampilkan tombol gabung grup setelah formulir berhasil dikirim (tautan ini disembunyikan dari pembacaan halaman sebelum submit). Jika panitia perlu membatasi kuota per angkatan, aktifkan toggle opsional **Batasi kuota peserta per angkatan (opsional)** (default nonaktif), gunakan preset cepat **2023-2026 @ 5 peserta** atau tambah/hapus angkatan 4 digit hingga 20 entri (`MAX_COHORT_TIERS = 20`); saat aktif, kolom bawaan **Angkatan** otomatis dikunci ke `Wajib`, dan jika `registrationMaxQuota` juga diisi maka kedua batas berlaku bersamaan.
7. Pada kartu **Susunan kolom formulir**, sesuaikan **Kolom bawaan formulir** (`Wajib`, `Opsional`, atau `Disembunyikan` untuk `angkatan`, `noHp`, `idLine`, `email`, dan `catatan`; `Nama lengkap` dan `NIM` selalu wajib, serta `Angkatan` dikunci ke `Wajib` selama kuota per angkatan aktif) serta tambahkan **Pertanyaan tambahan custom** (hingga 20 kolom) bila diperlukan.
8. Klik **Simpan pengaturan formulir** (`PATCH /api/admin/programs/<id>/form`).
9. Salin jalur `/program-kerja/<id>/daftar` dari kotak **Tautan formulir pendaftaran publik** pada kartu **Akses, kuota & tautan grup** melalui tombol **Salin tautan** atau uji lewat **Buka halaman**.
